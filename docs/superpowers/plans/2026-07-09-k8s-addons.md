# K8s Addons Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Instalar MetalLB, ingress-nginx e cert-manager (com certificado wildcard Let's Encrypt DNS-01/Google Cloud DNS) via Terraform + provider helm, num único `terraform apply`.

**Architecture:** Novo módulo `modules/k8s-addons` com 5 `helm_release` encadeados por `depends_on`. Custom resources (IPAddressPool, L2Advertisement, ClusterIssuer, Certificate, Secret) vivem em dois mini-charts locais (`charts/metallb-config`, `charts/cert-infra`) para evitar o problema de CRD-no-plan. Tráfego: DNS público → IP OVH 139.99.62.36 → DNAT no host Proxmox → VIP MetalLB 10.10.10.100 → ingress-nginx com wildcard como certificado default.

**Tech Stack:** Terraform 1.14 (roda na máquina `architect` via túnel SSH), provider `hashicorp/helm ~> 2.17`, Helm charts: metallb 0.14.9, ingress-nginx 4.12.1, cert-manager v1.16.3.

- [ ] **Step 1: Criar scripts/get-kubeconfig.sh**

```bash
#!/usr/bin/env bash
# Busca o kubeconfig do control plane e ajusta para acesso via tunel SSH.
# Uso: ./scripts/get-kubeconfig.sh   (rodar na raiz do repo, na maquina architect)
set -euo pipefail

JUMP="root@139.99.62.36"
CONTROL_PLANE="ubuntu@10.10.10.50"
OUT="./kubeconfig"

scp -o ProxyJump="$JUMP" "$CONTROL_PLANE:/home/ubuntu/.kube/config" "$OUT"

# API só é alcançável pelo túnel; o cert do apiserver não tem SAN para 127.0.0.1,
# então fixamos tls-server-name no nome interno "kubernetes".
sed -i 's|server: https://.*|server: https://127.0.0.1:6443\n    tls-server-name: kubernetes|' "$OUT"
chmod 600 "$OUT"

echo "kubeconfig salvo em $OUT"
echo "Abra o túnel antes do terraform apply:"
echo "  ssh -fN -L 6443:10.10.10.50:6443 $JUMP"
```

- [ ] **Step 2: Criar scripts/proxmox-dnat.sh**

```bash
#!/usr/bin/env bash
# Roda NO HOST PROXMOX (root). Encaminha 80/443 do IP publico para o VIP do
# ingress-nginx (MetalLB). Idempotente: -C testa antes de -A.
set -euo pipefail

PUBLIC_IP="139.99.62.36"
INGRESS_VIP="10.10.10.100"

sysctl -w net.ipv4.ip_forward=1 >/dev/null

for PORT in 80 443; do
  iptables -t nat -C PREROUTING -d "$PUBLIC_IP" -p tcp --dport "$PORT" \
    -j DNAT --to-destination "$INGRESS_VIP:$PORT" 2>/dev/null ||
    iptables -t nat -A PREROUTING -d "$PUBLIC_IP" -p tcp --dport "$PORT" \
      -j DNAT --to-destination "$INGRESS_VIP:$PORT"

  iptables -C FORWARD -d "$INGRESS_VIP" -p tcp --dport "$PORT" -j ACCEPT 2>/dev/null ||
    iptables -A FORWARD -d "$INGRESS_VIP" -p tcp --dport "$PORT" -j ACCEPT
done

# Persistencia entre reboots
if command -v netfilter-persistent >/dev/null; then
  netfilter-persistent save
else
  echo "AVISO: instale iptables-persistent para persistir as regras:"
  echo "  apt-get install -y iptables-persistent && netfilter-persistent save"
fi

echo "DNAT ativo: $PUBLIC_IP:80/443 -> $INGRESS_VIP"
```
